# Sudarshan Dhage

Software engineer working across mobile clients and the backend services behind them.

I care about systems that are simple to reason about a year after they ship: explicit data models, boring control flow, and failure modes that were considered before they occurred in production.

## What I work on

**Cross-platform mobile.** Flutter applications with predictable state management, offline-tolerant data flow, and real-time synchronisation through Firebase. Reliable behaviour on poor networks is a design requirement, not a bug fix.

**Backend services.** Node.js and Spring Boot services with versioned REST contracts, queue-backed asynchronous work, and clear boundaries between transport, domain logic, and persistence.

**Applied AI.** LLM capabilities integrated into product flows with structured output, schema validation, retries, and deterministic fallbacks, so a model failure degrades the feature rather than the application.

## How I approach the work

- Model the domain before writing the endpoint. Most defects are contract problems in disguise.
- Instrument from the first commit. Logs, metrics, and traces are cheaper to add early than to retrofit during an incident.
- Automate the repeatable parts: pipelines, container-based environments, and integration tests against real dependencies.
- Use AI assistance for velocity, and hold the output to the same review standard as anything else.
